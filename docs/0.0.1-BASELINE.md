# QYQ OS 0.0.1 Baseline

QYQ OS 0.0.1 is the first bootable development baseline.

## Version Baseline

- QYQ OS: **0.0.1**
- Base distribution: **Debian 13.7 (Trixie)**
- Distribution track: **Debian 13 Stable / LTS**
- Kernel line: **Linux 6.12**
- Init / service manager: **systemd 257.x**
- Package manager: **APT 3.0.x + dpkg**
- Primary architecture: **amd64 / x86-64**
- Firmware target: **UEFI**
- First execution target: **QEMU**
- Filesystem: **ext4**
- Network: Debian default userspace networking sufficient for QEMU
- Desktop environment: **None in 0.0.1**
- AI models: **None in 0.0.1**
- Agent Runtime: **None in 0.0.1**

## Pinning Policy

QYQ OS pins the major platform baseline, not every security patch.

The 0.0.1 baseline is built from Debian 13.7, but security and critical bug-fix updates within Debian 13 are allowed.

The kernel remains on the Debian 13 Linux 6.12 line and follows Debian security updates instead of pinning a single patch release permanently.

This keeps QYQ OS reproducible while avoiding intentional exposure to already-fixed security issues.

## 0.0.1 Goal

The goal of 0.0.1 is to establish a minimal QYQ OS that can be built repeatedly and booted reliably.

A successful 0.0.1 must:

1. Build a QYQ OS disk/system image from a documented build process.
2. Boot through UEFI in QEMU.
3. Reach a working systemd userspace.
4. Provide a local shell/login.
5. Bring up networking.
6. Use APT successfully.
7. Identify itself as QYQ OS while retaining Debian compatibility information where required.
8. Contain the initial QYQ OS package/repository configuration.
9. Produce enough build metadata to reproduce the image.

## Explicitly Out of Scope

The following are intentionally deferred:

- Desktop environment
- Main Model
- Specialized Models
- Agent Runtime
- Memory Service
- Context Broker
- Permission Broker
- System Ledger
- Autonomous download and installation

The first Agent-native feature begins after this baseline is stable.

## Next Milestone

After 0.0.1:

> Autonomous software acquisition and installation.

The system will accept a high-level task such as:

```text
Install Blender
```

and execute the necessary search, resolution, download, verification, security checks, permission checks, installation, validation, and logging steps.
