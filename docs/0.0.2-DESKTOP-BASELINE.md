# QYQ OS 0.0.2 — Desktop Baseline

## Goal

QYQ OS 0.0.2 establishes the first graphical desktop baseline.

The release should boot from UEFI into a graphical login screen and provide a usable KDE Plasma desktop suitable for future Agent demonstrations.

## Product Identity

- Product name: QYQ OS
- Full English name: QiYinQiao Operating System
- Chinese name: 七音桥 操作系统
- Version: 0.0.2
- Base: Debian 13 (Trixie)
- Architecture: amd64
- Display stack: Wayland
- Desktop: KDE Plasma 6
- Display manager: SDDM
- Logo: intentionally unspecified for 0.0.2

## Scope

0.0.2 should provide:

1. UEFI boot
2. Linux/systemd base inherited from 0.0.1
3. KDE Plasma desktop
4. Wayland session support
5. SDDM graphical login
6. Working keyboard and mouse under QEMU
7. Working virtual display under QEMU
8. Working networking
9. Working APT
10. Basic QYQ OS textual branding
11. Chinese font support
12. A development user that can log in to the desktop
13. Automated CI checks confirming the graphical boot target and SDDM are enabled

## Desktop Package Strategy

Do not install the full Debian `task-kde-desktop` task in 0.0.2.

Use a smaller desktop baseline centered on:

- `kde-standard`
- `sddm`
- `plasma-workspace`
- `kwin-wayland`
- `network-manager`
- `fonts-noto-cjk`
- `spice-vdagent`
- `qemu-guest-agent`

The objective is a normal usable Plasma desktop without preinstalling a large productivity application set.

## Login

Development account:

```text
username: qyq
password: qyq
```

This account remains development-only and must not be treated as a production installer design.

## Boot Target

0.0.2 changes the default systemd target from:

```text
multi-user.target
```

to:

```text
graphical.target
```

SDDM should start automatically.

## Branding

For 0.0.2 branding remains intentionally minimal:

```text
QYQ OS 0.0.2
QiYinQiao Operating System
七音桥 操作系统
```

No logo or custom visual identity is required yet.

Do not fork or heavily modify the KDE Plasma theme for this release.

## Networking

The desktop should use NetworkManager so future desktop controls and Agent tooling can query and manage networking through standard Linux interfaces.

## QEMU Baseline

The graphical image should remain testable in QEMU.

Recommended development VM:

- machine: q35
- firmware: UEFI / OVMF
- RAM: 4 GiB
- CPUs: 4
- disk: virtio
- network: virtio
- display: virtio-vga / compatible virtual GPU

## Image Size

Increase the development raw image from 4 GiB to 12 GiB to accommodate Plasma and future desktop work.

## Automated Verification

CI cannot fully replace human GUI validation.

Automated 0.0.2 checks should verify at minimum:

- UEFI/Linux boot succeeds
- QYQ OS 0.0.2 identity is present
- `graphical.target` is the default target
- SDDM is installed and enabled
- Plasma/Wayland packages are present

Human validation should verify:

- SDDM graphical login appears
- user `qyq` can log in
- Plasma desktop appears
- keyboard and mouse work
- networking works
- a terminal can be opened
- `sudo apt update` works

## Out of Scope

0.0.2 does not include:

- Agent Runtime
- Task Runtime
- Main Model
- specialized AI models
- Memory Service
- Context Broker
- Permission Broker
- System Ledger
- autonomous software installation
- final QYQ visual branding or logo

These capabilities will build on top of the graphical baseline.
